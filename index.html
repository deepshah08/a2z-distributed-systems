Part I

Time, Ordering & Global State

In an asynchronous network, there is no shared physical clock and no global shared memory. This part explores clock drift physics, logical clocks, vector clocks, and non-blocking distributed snapshot algorithms.

01Physical Clocks

Physical Clocks, Skew & Google TrueTime

Quartz crystal oscillators inside server hardware drift by up to $10\text{--}100\text{ ppm}$ ($\sim 1\text{ second}$ every $10\text{ days}$). Traditional NTP synchronization introduces unbounded network jitter ($10\text{--}100\text{ms}$). Google TrueTime addresses this by returning a bounded interval $[t - \epsilon, t + \epsilon]$ backed by atomic clocks and GPS receivers.

The TrueTime Guarantee: If transaction $T_1$ commits before $T_2$ begins in real physical time, then $s_1 < s_2$ where $s$ is the TrueTime commit timestamp.
02Logical Time

Logical Clocks & Lamport Timestamps

In his seminal 1978 paper, Leslie Lamport proved that physical clocks are unnecessary to establish causal ordering. The Happens-Before relation ($\to$) defines: (1) events in the same process occur in order; (2) message sending happens before message receipt; (3) transitivity. Lamport timestamps update via $L(e) = \max(L_{\text{local}}, L_{\text{msg}}) + 1$.

03Causality

Vector Clocks & Causal Consistency

While Lamport timestamps guarantee that $a \to b \implies L(a) < L(b)$, the converse is false (two events with $L(a) < L(b)$ may be concurrent). Vector Clocks maintain an array of size $N$, allowing nodes to mathematically distinguish causal predecessors from concurrent sibling conflicts ($V_A \not\le V_B \land V_B \not\le V_A$).

04Snapshots

Global State & Chandy-Lamport Snapshots

Capturing the global state of a distributed system without pausing execution requires finding a Consistent Cut. The Chandy-Lamport algorithm propagates special Marker tokens through FIFO communication channels, recording local process states and capturing in-flight channel messages.

Part II

Failure Detection, Membership & Coordination

Determining whether a remote machine has crashed or is merely experiencing a temporary network delay is a fundamental challenge. This section covers accrual failure detection, epidemic gossip meshes, and distributed coordination algorithms.

05Failure Detectors

Unreliable Failure Detectors & Φ-Accrual

Binary heartbeat timeouts (e.g. 5 seconds) trigger false failovers during transient garbage collection pauses or network congestion. The $\Phi$-Accrual Failure Detector outputs a continuous suspicion scale $\Phi = -\log_{10}(P_{\text{later}}(t - t_{\text{last}}))$ based on a sliding window of historical heartbeat intervals.

06Gossip Protocols

Gossip Protocols & The SWIM Membership Mesh

Traditional heartbeat broadcasts generate $\mathcal{O}(N^2)$ network messages, collapsing large clusters. The SWIM protocol achieves $\mathcal{O}(1)$ message overhead per node using randomized direct pings and multi-hop indirect ping-req probes to eliminate false positives.

07Mutual Exclusion

Distributed Mutual Exclusion: Ricart-Agrawala

Contending for a shared critical section across network nodes can be resolved without a central coordinator. The Ricart-Agrawala algorithm exchanges $2(N - 1)$ timestamped REQUEST and OK messages, prioritizing nodes with lower Lamport timestamps.

08Leader Elections

Leader Election Algorithms: Bully vs. Ring

When a coordinator crashes, surviving nodes must elect a replacement. The Bully Algorithm allows higher-ranked nodes to assert dominance via $\mathcal{O}(N^2)$ broadcasts. The Chang-Roberts Ring Algorithm circulates election tokens unidirectionally in $\mathcal{O}(N \log N)$ average messages.

Part III

Consensus & Fault Tolerance

Reaching agreement across unreliable nodes forms the backbone of distributed state machines. This part examines FLP impossibility, Classical Multi-Paxos (HDFS QJM), Raft log replication, and Byzantine Fault Tolerance.

09Impossibility Results

The Consensus Hierarchy & FLP Impossibility

The 1985 Fischer-Lynch-Paterson (FLP) theorem proved that in a purely asynchronous network, no deterministic consensus protocol can guarantee termination in the presence of even a single unannounced crash failure.

The Bivalent State: An adversary can perpetually delay network messages to prevent a bivalent configuration (where both 0 and 1 are reachable) from collapsing into a decided univalent state.
10Paxos Foundations

Classical Paxos: Multi-Paxos & HDFS QJM

Leslie Lamport's Paxos protocol guarantees safety under arbitrary asynchronous delays. In high-throughput systems like the HDFS Quorum Journal Manager (QJM), Multi-Paxos amortizes Phase 1 (Prepare/Promise) across a stable leader, committing edits in Phase 2 (Accept/Accepted) with majority quorum acknowledgments.

11Raft Protocol

The Raft Protocol: Log Matching & Safety

Raft decomposes distributed consensus into understandable modules: randomized election timeouts, strict term numbers, and leader-driven log replication. The Log Matching Property guarantees that if two logs contain an entry with the same index and term, all preceding entries are identical.

12Byzantine Faults

Byzantine Fault Tolerance: The PBFT Protocol

While Crash Fault Tolerant (CFT) protocols tolerate fail-stop nodes, Byzantine Fault Tolerant (BFT) systems tolerate malicious nodes that lie or forge conflicting messages. Miguel Castro and Barbara Liskov introduced PBFT, proving that $N \ge 3f + 1$ nodes are required to tolerate $f$ Byzantine traitors.

Part IV

Replication & Distributed Storage

Applying consensus and replication to build durable, linearizable storage systems: primary-backup trade-offs, Dynamo read repair, atomic commit protocols, and Google Spanner TrueTime commit-wait.

13Data Replication

Replication Models: Synchronous vs. Asynchronous

Primary-backup architectures trade off write latency against data loss risk. Synchronous replication guarantees zero replication lag but blocks writes on the slowest backup. Asynchronous replication returns immediately but risks losing un-replicated write log entries during primary crashes.

14Anti-Entropy

Quorums, Read Repair & Hinted Handoff

Leaderless systems (Amazon Dynamo, Apache Cassandra) maintain high write availability by accepting writes to healthy nodes and recording Hinted Handoffs for offline replicas. When client quorum reads detect inconsistent versions, Read Repair reconciles stale replicas in the background.

15Transactions

Distributed Commit: 2PC vs. Skeen's 3PC

Two-Phase Commit (2PC) guarantees all-or-nothing atomicity across databases but is a blocking protocol: if the coordinator crashes during the Prepared phase, cohorts hold row locks indefinitely. Dale Skeen's Three-Phase Commit (3PC) introduces a Pre-Commit phase to make commit decisions non-blocking under synchronous network bounds.

16External Consistency

Modern Distributed Storage: Google Spanner & TrueTime

Google Spanner achieves global external consistency (linearizability) across multi-continent datacenters using TrueTime Commit-Wait. Leaders pick commit timestamps equal to the upper bound of the current TrueTime uncertainty window and wait $2\epsilon$ before releasing locks, guaranteeing monotonically increasing commit timestamps globally.
